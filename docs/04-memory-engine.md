# 04 — Memory Engine

> **This is the product.** Everything else can be adequate; this must be excellent.
> **Status:** Authoritative. Algorithm constants are tunable; the pipeline shape is not.

---

## 1. What the memory engine is responsible for

| Responsibility | Consequence if done badly |
|---|---|
| Deciding what is worth remembering | Storage exhaustion, or an amnesiac world |
| Storing it in a retrievable shape | Facts exist but never surface |
| Retrieving the *right* memories for *this* moment | Characters recall irrelevant trivia and miss the promise you made |
| Enforcing who knows what | Secrets leak; the world stops feeling real |
| Merging duplicates and resolving contradictions | The world contradicts itself and the illusion dies |
| Ageing gracefully over months | Retrieval quality decays as the world grows — the failure that kills long-term retention |

## 2. Memory taxonomy

Six kinds. The `kind` column drives ranking weights, decay rates and prompt placement.

| Kind | Answers | Example | Decay | Typical importance |
|---|---|---|---|---|
| `episodic` | What happened | *"On day 14, the user rescued Elena from the dungeon."* | Medium | 0.3–0.9 |
| `semantic` | What is true | *"Elena distrusts the royal family."* | Very slow | 0.4–0.8 |
| `relational` | How they feel and why | *"Elena's trust rose after the user defended her publicly."* | Slow | 0.4–0.9 |
| `world` | What changed globally | *"The king died. War began on day 94."* | None | 0.7–1.0 |
| `persona` | About the player | *"The user prefers swords and refuses to lie."* | Slow | 0.3–0.7 |
| `reflection` | A synthesised insight | *"The user consistently protects the weak, even at personal cost."* | Slow | 0.6–0.9 |

`reflection` memories are generated by consolidation, never by extraction. They are the cheapest way to give a character an opinion about the player that spans a hundred turns.

## 3. Writing rules

Every memory row obeys these invariants. They are enforced by validation, not by hope.

1. **One fact per row.** *"The user gave Elena a sword and told her about the king"* is two memories.
2. **Third person, past tense, self-contained.** *"He said he would"* is useless in three weeks. *"The user promised Elena he would return before sunset on day 14"* is not.
3. **Names, not pronouns.** Resolve every reference at write time; the retrieval context is not the writing context.
4. **Day-stamped** when the fact is time-bound.
5. **≤ 200 characters.** Longer means it is not one fact.
6. **Never store the user's raw message.** Store the extracted fact. Raw text lives in `messages` and is not memory.

## 4. Extraction

### When

After the commit step, asynchronously ([02](02-system-architecture.md) § 4). Never in the request path.

Runs on a **rolling window of the last N turns** (default 3) rather than per message, so that multi-turn facts are captured — a promise made across two messages is one memory.

### Selectivity target

**≤ 3 memories per 10 turns** at default `memory_aggressiveness = 0.5`. If extraction is producing more than that, the prompt is wrong, not the world.

A memory earns its row only if a human would answer yes to: *would it be strange if a character forgot this in two weeks?*

### The extraction call

Task class `extract`, routed to the fast tier ([08](08-ai-router.md)). Structured output, validated with Zod. On parse failure: one retry with a repair instruction, then drop the batch and log — a lost memory is acceptable; a corrupt one is not.

```jsonc
// Response schema (packages/contracts/memory.ts)
{
  "memories": [
    {
      "kind": "episodic",
      "content": "The user promised Elena he would return before sunset on day 14.",
      "subjects": ["persona:me", "character:elena"],
      "importance": 0.85,
      "confidence": 0.95,
      "world_day": 14,
      "known_by": ["character:elena"],      // knowledge isolation, at birth
      "visibility": "restricted"
    }
  ],
  "relationship_deltas": [
    { "from": "character:elena", "to": "persona:me",
      "deltas": { "trust": 3, "affection": 2 },
      "reason": "He kept his word about her brother." }
  ],
  "world_changes": [
    { "op": "set_flag", "key": "elena_trusts_user", "value": true }
  ],
  "events": [
    { "title": "Promise at the gate", "event_type": "social",
      "importance": 0.7, "participants": ["character:elena"] }
  ],
  "contradictions": [
    { "memory_id": "…", "reason": "Elena was earlier recorded as not knowing about the sword." }
  ]
}
```

### Importance scoring

The model proposes importance; the backend adjusts it deterministically. Never trust a model's self-reported salience alone.

```
importance = clamp(0.05, 1.0,
    0.45 · model_importance
  + 0.20 · kind_prior[kind]
  + 0.15 · subject_centrality        // involves the persona? a main character?
  + 0.10 · emotional_charge          // classifier score, cheap
  + 0.10 · irreversibility           // death, betrayal, promise, oath → high
)
```

`irreversibility` is the underrated term. Facts that cannot be undone are the ones players remember, and therefore the ones the world must remember.

### Anti-duplication at write time

Before insert, run a cheap similarity check against the world's existing memories:

```
if cosine(new, existing) > 0.92 and same kind:
      merge — bump importance, update access, do not insert
elif cosine(new, existing) > 0.85:
      insert, then link (relation = 'elaborates')
else: insert
```

This is one extra vector query per candidate memory and it prevents the single most common failure mode: five rows all saying the user owns Ravenblade.

## 5. Retrieval — the hot path

Retrieval runs **per responding character**, because two characters in the same scene must get different results.

```
                    ┌───────────────────────┐
  user message  ──▶ │  Query construction   │
  scene context     └───────────┬───────────┘
                                │  query text + subject filter + character id
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
  ┌───────────┐          ┌────────────┐          ┌─────────────┐
  │  Vector   │          │  Keyword   │          │  Structural │
  │  (HNSW)   │          │  (tsvector │          │  pinned +   │
  │  top 40   │          │   + trgm)  │          │  recent +   │
  └─────┬─────┘          │  top 40    │          │  subject-   │
        │                └──────┬─────┘          │  matched    │
        │                       │                └──────┬──────┘
        └───────────┬───────────┴───────────────────────┘
                    ▼
          ┌──────────────────────┐
          │ Reciprocal Rank      │   RRF: score = Σ 1/(k + rank_i), k=60
          │ Fusion               │
          └──────────┬───────────┘
                     ▼
          ┌──────────────────────┐
          │ KNOWLEDGE FILTER     │   ← non-negotiable, SQL-level
          └──────────┬───────────┘
                     ▼
          ┌──────────────────────┐
          │ Composite re-rank    │   § 6
          └──────────┬───────────┘
                     ▼
          ┌──────────────────────┐
          │ MMR diversification  │   λ = 0.7
          └──────────┬───────────┘
                     ▼
          ┌──────────────────────┐
          │ Token-budget packing │   § 7
          └──────────┬───────────┘
                     ▼
              8–15 memories
```

### Query construction

The retrieval query is **not** the raw user message. It is:

```
query_text = user_message
           + " " + last_2_character_lines
           + " " + current_scene_summary
           + " " + extracted_entities(user_message)
```

Entity extraction here is regex + a per-world alias table (character names, location names, item names), not an LLM call. Names are the highest-signal retrieval term and exact matching finds them better than embeddings do.

### Knowledge isolation — the SQL

This is the most important query in the system. It runs as part of retrieval and cannot be bypassed.

```sql
-- Memories a given character is permitted to recall.
SELECT m.*
FROM memories m
WHERE m.world_id = $world_id
  AND m.deleted_at IS NULL
  AND m.superseded_by IS NULL
  AND (
        m.visibility = 'world'
     OR EXISTS (
          SELECT 1 FROM character_knowledge ck
          WHERE ck.memory_id = m.id
            AND ck.character_id = $character_id
            AND ck.knows
        )
  )
```

Three rules follow, and violating any of them is a P1 bug:

1. **Never** retrieve without this predicate and then filter in application code.
2. **Never** instruct the model to "pretend not to know" something. Models leak under pressure; a `WHERE` clause does not.
3. The **narrator** has world-scope visibility. Characters do not.

## 6. The ranking formula

After fusion, every candidate is scored:

```
score(m) =  w_sim · similarity(m, query)          // 0..1, from RRF-normalized rank
          + w_rec · recency(m)
          + w_imp · m.importance
          + w_rel · character_relevance(m, c)
          + w_top · topic_overlap(m, scene)
          + w_acc · access_boost(m)
          + w_pin · (m.is_pinned ? 1 : 0)
          − w_red · redundancy(m, already_selected)
```

### Default weights

| Term | Weight | Notes |
|---|---|---|
| `w_sim` | 0.30 | Necessary, not sufficient. Pure vector search retrieves plausible-sounding irrelevance. |
| `w_rec` | 0.15 | |
| `w_imp` | 0.20 | |
| `w_rel` | 0.15 | 1.0 if the character is in `subjects`, 0.5 if a linked memory is, else 0.1 |
| `w_top` | 0.10 | Jaccard overlap of entities between memory and current scene |
| `w_acc` | 0.05 | Frequently-recalled memories are load-bearing for the story |
| `w_pin` | 1.00 | Pinned memories bypass ranking entirely — they are always included |
| `w_red` | 0.25 | Penalty against already-selected memories |

**These weights are hypotheses.** They are tuned against the retrieval benchmark ([15](15-testing-and-evaluation.md) § Memory Benchmark) and every change must show a measured improvement. Weights live in `packages/core/memory/weights.ts` as named constants, versioned, never inline.

### Recency

Exponential decay with a per-kind half-life measured in **world days**, not wall-clock days — a world played intensely over one weekend covering 200 in-world days should age its memories accordingly.

```
recency(m) = exp( −ln(2) · (current_world_day − m.world_day) / halflife[m.kind] )

halflife = { episodic: 30, semantic: 365, relational: 90,
             world: ∞, persona: 180, reflection: 180 }
```

`world` memories never decay. The king staying dead is not negotiable.

### Redundancy (MMR)

Greedy selection maximizing marginal relevance:

```
next = argmax_m [ λ · score(m) − (1−λ) · max_{s ∈ selected} cosine(m, s) ],  λ = 0.7
```

Without this, retrieval returns eight near-identical memories about the same event and the character sounds obsessive.

## 7. Token budget packing

The context builder gives memory a **fixed token budget** ([09](09-context-builder-and-prompts.md)). Retrieval fills it in priority order:

| Priority | Slot | Budget share | Rule |
|---|---|---|---|
| 1 | Pinned | up to 15% | Always. Truncate the pin list before dropping anything else, and warn the user in the UI if pins exceed the slot. |
| 2 | Relationship state | 10% | Compact numeric summary, not prose |
| 3 | Top-ranked memories | 50% | From § 6 |
| 4 | Recent events | 15% | Last 3 world events |
| 5 | Contextual world rules | 10% | Keyword-matched only ([05](05-world-engine.md)) |

Overflow is **dropped from the bottom**, never truncated mid-memory. A half-sentence memory is worse than an absent one.

Target: **8–15 memories per character per turn.** Beyond ~20, measured recall quality falls — the model starts averaging across them instead of using them.

## 8. Consolidation

Runs as a background job when a world crosses a threshold (default: 50 new memories since last run, or 7 days elapsed).

### Four operations

**a) Merge near-duplicates.** Cluster by cosine ≥ 0.88 within the same kind, then rewrite the cluster as one memory. Sum importance with diminishing returns (`1 - Π(1 - imp_i)`), preserve the earliest `world_day`, mark the originals `superseded_by`.

```
BEFORE                                    AFTER
User owns a sword.                        The user owns Ravenblade,
User owns Ravenblade.              ──▶    a legendary sword taken
User has Ravenblade.                      from the dungeon on day 12.
Ravenblade belongs to the user.
```

**b) Resolve contradictions.** When `memory_links.relation = 'contradicts'` exists, apply this precedence:

```
1. user-edited      (is_user_edited)          — the user is always right
2. authoritative    (derived from world_state) — the database beats prose
3. more recent      (higher world_day)
4. higher confidence
5. higher importance
```

The loser is marked `superseded_by`, never deleted. Deletion loses the audit trail we need to debug bad recall.

**c) Generate reflections.** Every ~100 memories, ask the deep tier for 1–3 higher-order observations about the persona or a character. This is what produces *"the user consistently protects the weak"* from fifty individual rescues, and it is disproportionately what makes a world feel like it knows you.

**d) Prune.** Soft-delete memories where `importance < 0.15 AND access_count = 0 AND age > 60 world days AND NOT is_pinned AND NOT is_user_edited`. Drop the embeddings of superseded memories immediately — that is the largest storage win available ([01](01-principles-and-constraints.md) § Storage math).

**Consolidation never deletes a user-edited or pinned memory. Ever.**

## 9. User-facing memory — the Memory Notebook

Exposing memory is a feature, not a debug tool. It converts the system's biggest liability (occasional wrong recall) into a trust-building interaction.

Users can:

| Action | Effect |
|---|---|
| **View** | Grouped by importance, kind and timeline |
| **Pin** | `is_pinned = true` — always retrieved, bypasses ranking |
| **Edit** | Rewrites content, sets `is_user_edited`, re-embeds, and wins all future contradiction resolution |
| **Delete** | Soft-delete, immediately excluded from retrieval |
| **Add** | Manual memory at importance 0.8, `is_user_edited = true` |
| **Inspect** | "Why did she say that?" → shows the exact memories retrieved for that turn |

That last one is a Phase 12 feature and it is worth building. It is the single most convincing demonstration that this is not a chatbot, and it is also the best debugging tool we will have.

**Availability:** view/pin/edit/delete are available on the **free tier**. Memory is not paywalled ([01](01-principles-and-constraints.md) § B4).

## 10. Embeddings

```ts
interface EmbeddingProvider {
  readonly id: string;          // 'workers-ai:bge-base-en-v1.5'
  readonly dimensions: number;  // must be 768 for the current schema
  readonly version: number;
  embed(texts: string[]): Promise<Float32Array[]>;
}
```

**Rules:**

- Embedding is **always** a background job. Never on the request path.
- A memory without an embedding is still retrievable by keyword and structure. Retrieval must degrade, not fail, when embeddings lag.
- `embedding_model` and `embedding_version` are stored per row. A provider change enqueues a re-embed job over the affected rows, processed at a rate that respects free-tier limits.
- Batch aggressively — most free embedding endpoints price per call, not per token.
- **Cache by content hash.** Identical text across worlds embeds once.

Provider order for evaluation in Phase 1 (measure, then decide — record in an ADR):

1. A hosted free embedding endpoint (Workers AI or equivalent free tier)
2. A second hosted free endpoint as fallback
3. Local ONNX embedding in the job runner (only if the runner moves off Workers)

## 11. Failure modes and their handling

| Failure | Detection | Response |
|---|---|---|
| Embedding provider down | Job failures | Queue embeddings; retrieval falls back to keyword + structural. **Never block a turn.** |
| Retrieval returns nothing | Empty result | Fall back to: recent events + relationship state + last 6 turns. The turn still happens. |
| Extraction produces garbage | Zod validation fails | Retry once with a repair prompt, then drop and log. Never insert unvalidated rows. |
| Contradictory memories surfaced together | `contradicts` link exists at retrieval | Include only the winner by § 8b precedence; flag for consolidation |
| Character recalls something they should not know | **P1 bug** | Isolation query is wrong. Halt, reproduce with the leakage test ([15](15-testing-and-evaluation.md)), fix, add a regression case. |
| Retrieval latency > 400 ms p95 | Metric | Check HNSW `ef_search`; reduce candidate pool from 40 to 25; add covering index. |
| World exceeds ~5,000 memories | Metric | Consolidation is under-running. Raise its frequency; check the prune predicate. |

## 12. Interface

```ts
// packages/contracts/memory.ts

interface MemoryEngine {
  retrieve(input: {
    worldId: string;
    characterId: string | null;      // null = narrator / world scope
    queryText: string;
    sceneEntities: string[];
    tokenBudget: number;
    currentWorldDay: number;
  }): Promise<RetrievedMemory[]>;

  extract(input: {
    worldId: string;
    turnIds: string[];               // rolling window
    aggressiveness: number;          // 0..1 from world_settings
  }): Promise<ExtractionResult>;

  consolidate(worldId: string, opts?: { force?: boolean }): Promise<ConsolidationReport>;

  // User-facing operations
  pin(memoryId: string, pinned: boolean): Promise<void>;
  edit(memoryId: string, content: string): Promise<Memory>;
  remove(memoryId: string): Promise<void>;
  add(worldId: string, input: NewMemory): Promise<Memory>;
  explainTurn(turnId: string): Promise<RetrievalTrace>;   // Phase 12
}
```

`RetrievalTrace` records, per turn: the query text, every candidate with its per-term score contributions, what was selected, and what was cut by budget. Storing it for the last N turns costs little and makes every "why did she say that?" question answerable.
